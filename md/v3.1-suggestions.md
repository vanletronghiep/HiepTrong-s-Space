## How to read this document

- **Covered** items are already inside the approved v3.1 plan; their outcome is tracked here.
- **Pending owner review** items are additional proposals. They are *not* approved requirements
  and were not implemented. Add your decision in the `Owner decision` line.
- Types: **Confirmed bug** (reproduced or proven by test), **Suspected problem** (strong evidence,
  not reproduced end to end), **Design recommendation** (subjective), **Feature idea** (new
  capability), **Technical debt**.
- Priority: P1 (fix soon) · P2 (worthwhile) · P3 (nice to have).

## Covered by the approved v3.1 plan

### C-01 · Large frame around the Daily page after Win + Shift + S (img35)
- **Component:** `src/ui/WorkspaceShell.tsx` (`<main id="main-content" tabIndex={-1}>`), `src/app/globals.css`
- **Type:** Confirmed bug (root cause identified in code; see browser verification notes in the final handoff)
- **Evidence:** `main` is focusable (`tabIndex={-1}`) as the skip-link target, so a mouse click on empty page space focuses it. Keyboard input outside the page (Win + Shift + S) sets Chrome's keyboard modality, and on window refocus Chrome re-matches `:focus-visible` on the still-focused `main`, drawing the global 2 px outline around the whole content box.
- **Outcome:** Fixed under [plan §3.1](v3.1-implementation-plan.md#31-borderless-focus-feedback). Non-interactive programmatic focus targets (`main`, `section`, `article`, `div`, headings, lists with `tabindex="-1"`) keep semantic focus but draw no frame. Interactive controls keep their visible feedback.

### C-02 · Route readiness signalled before data was usable
- **Component:** 11 feature routes under `src/app/(workspace)/*/page.tsx`
- **Type:** Confirmed bug
- **Evidence:** Events, Achievements, AI Engineering, APCS, Blogs, Entertainment, Flashcards, Learning Room, Milestones, Projects, and Tracking all mounted `<PageReady />` beside the view, so the transition ended while the view was still showing skeletons.
- **Outcome:** Fixed under [plan §3.2](v3.1-implementation-plan.md#32-destination-zodiac-loading). Each view now signals readiness once its primary query has data or a visible error.

### C-03 · Old Event drafts could erase a stored end time on publish
- **Component:** `src/services/event-draft-service.ts`
- **Type:** Confirmed bug (found while adding end-time support; covered by a regression test)
- **Evidence:** Drafts created before v3.1 (including browser-stored drafts imported later) carry no end fields. Without special handling, publishing would have diffed an empty end against the stored end and cleared it.
- **Outcome:** Fixed under [plan §8.3](v3.1-implementation-plan.md#83-compatibility-and-migration). Missing v3.1 fields are taken from the source event at save and at publish time.

### C-04 · Hub note cards keep a fixed 240 px body
- **Component:** `src/features/tasks/task-note.module.css`
- **Type:** Design recommendation
- **Evidence:** Cards without a description still reserve the full 240 px, producing a large empty area.
- **Outcome:** Tracked under [plan §5 Task renovation](v3.1-implementation-plan.md#5-daily-task-management-and-tasks-hub-renovation); addressed by the mockup proposal awaiting owner review.

## Additional proposals — pending owner review

### A-01 · Weekly classes have no reminders
- **Component:** `src/services/timed-sources.ts`
- **Type:** Feature idea · **Priority:** P2
- **Evidence:** Reminders are generated once per stored event record. v3.1 deliberately excludes class series from reminders (expanding every weekly occurrence into notifications would be new product behaviour). A legacy School event converted to a class therefore stops producing its single reminder.
- **Proposal:** Optional per-class reminder (e.g. "remind me 30 minutes before each class"), generated only for the next occurrence.
- **Effort / dependencies:** Medium; touches notification rules and the occurrence resolver.
- **Risks:** Notification noise if enabled by default.
- **Owner decision:** _pending_

### A-02 · Deleting an ordinary event has no confirmation
- **Component:** `src/features/events/EventDetailPane.tsx`
- **Type:** Design recommendation · **Priority:** P2
- **Evidence:** Pre-existing behaviour preserved in v3.1: "Delete event" deletes immediately. Projects, Milestones, and Achievements already use `ConfirmDialog`.
- **Proposal:** Reuse `ConfirmDialog` for ordinary event deletion.
- **Effort:** Small. **Risks:** None significant.
- **Owner decision:** _pending_

### A-03 · Preparation task shows a raw ID
- **Component:** Events reader and detail metadata
- **Type:** Design recommendation · **Priority:** P3
- **Evidence:** `preparationTaskId` is displayed as an opaque identifier.
- **Proposal:** Resolve the linked task title and link to `/tasks/hub?task=<id>`.
- **Effort:** Small–medium (needs a task lookup on the Events page).
- **Owner decision:** _pending_

### A-04 · Legacy recurrence metadata on ordinary events is display-only
- **Component:** `src/contracts/event.ts` (`recurrence`)
- **Type:** Technical debt · **Priority:** P3
- **Evidence:** Ordinary events can carry daily/weekly/biweekly/monthly metadata that no code expands. v3.1 keeps it for compatibility (plan §8.1) and only executes weekly Class schedules.
- **Proposal:** Either hide the "Repeats …" line for ordinary events or convert such events explicitly, similar to Convert to class.
- **Owner decision:** _pending_

### A-05 · Most of the codebase is not Prettier-clean
- **Component:** repository-wide
- **Type:** Technical debt · **Priority:** P3
- **Evidence:** Running `npm run format` reflows about 90 files that v3.1 does not otherwise touch (long JSX lines, CSS one-liners, CRLF endings). v3.1 avoided this to keep its diff focused.
- **Proposal:** One dedicated formatting-only commit, kept separate from feature work.
- **Owner decision:** _pending_

### A-06 · Preview routes ship in production builds
- **Component:** `src/app/preview/*`
- **Type:** Suspected problem · **Priority:** P3
- **Evidence:** `/preview/events-pilot`, `/preview/homepage-pilot`, `/preview/shared-pilot`, `/preview/zodiac-illumination`, and `/preview/home-motion` are built and reachable. The Events pilot still shows the v2 editor.
- **Proposal:** Exclude previews from production (environment flag) or retire superseded pilots.
- **Owner decision:** _pending_

### A-07 · Documentation map links to missing files
- **Component:** `AGENTS.md`, `md/readme.md`, `md/agents/shared/uiux.md`
- **Type:** Technical debt · **Priority:** P3
- **Evidence:** Links to root `PROJECT_DESCRIPTION.md` and `plan.md` point to files that do not exist (noted in plan §1).
- **Proposal:** Restore an up-to-date engineering reference or remove the links.
- **Owner decision:** _pending_
